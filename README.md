# 📄 AI Document Intelligence

**An AI-powered PDF analysis system combining RAG, document summarization, and structured information extraction using Qwen3-14B.**

Transform PDF documents into searchable knowledge, concise summaries, and structured data through a simple Streamlit interface.

## ✨ Features

### 💬 1. Document Question Answering (RAG)

Ask questions about an uploaded PDF and receive answers grounded in the document.

- Semantic search using `intfloat/multilingual-e5-base`.
- Vector similarity search powered by FAISS.
- Retrieval of the four most relevant chunks for each question.
- Answers generated by Qwen3 using retrieved document context.
- Display of retrieved source chunks for verification.
- A fallback response when the retrieved context does not contain the answer.

### 📝 2. Document Summarization

Generate summaries in three formats:

| Summary Type         | Description                                           |
| -------------------- | ----------------------------------------------------- |
| **Short Summary**    | A single paragraph of up to 80 words                  |
| **Detailed Summary** | A detailed summary of approximately 250 words         |
| **Key Points**       | 5–10 bullet points highlighting important information |

For longer documents, the application uses a **map-reduce summarization strategy**:

1. **Map:** Split the document into chunks and summarize each chunk independently.
2. **Reduce:** Combine the partial summaries into one final summary while removing repetition.

### 🔎 3. Structured Information Extraction

Extract selected information from a PDF and return it as validated JSON.

The default schema includes:

- Document title
- Document type
- Main topic
- Key points
- Important entities

Example output:

```json
{
  "title": "Example Document",
  "document_type": "Report",
  "main_topic": "Artificial Intelligence",
  "key_points": ["First key point", "Second key point"],
  "important_entities": ["Example Entity"]
}
```

The extraction pipeline uses **Pydantic** to validate model output. If the generated response cannot be parsed or validated, the application retries using a correction prompt.

> Note: The model may return `null` or empty lists when the requested information cannot be found in the document.

### 🖥️ Local Environment

The local application handles:

- PDF parsing with Docling
- Text extraction and chunking
- Embedding generation
- FAISS indexing and retrieval
- Prompt construction
- Structured output validation
- Streamlit interface and result display

### ☁️ Kaggle Environment

The Kaggle notebook runs the language model and exposes an authenticated FastAPI endpoint through ngrok.

- Loads Qwen3-14B or a quantized AWQ variant when selected by the notebook's memory configuration.
- Provides a `POST /generate` endpoint.
- Uses Bearer-token authentication.
- Returns generated text to the local application.

### 🔐 Data Flow

Only the text required for a particular operation is sent to the Kaggle inference API:

- **RAG:** Retrieved context and the user's question.
- **Summarization:** The document text or its individual chunks.
- **Extraction:** The extracted document text.

The original PDF file is processed locally and is not uploaded to Kaggle as a PDF by this application. However, its extracted text may be sent to the model for processing.

## 🚀 Getting Started

### Prerequisites

- Python 3.10 or a compatible version supported by the installed dependencies
- Git
- A Kaggle account with access to a GPU-enabled notebook
- An ngrok account and authentication token
- A local machine capable of running Docling and the embedding model

The language model runs on Kaggle, so the local machine does not need to load Qwen3-14B.

### 1. Clone the Repository

```bash
git clone <YOUR_REPOSITORY_URL>
cd AI-Document-Intelligence
```

Replace `<YOUR_REPOSITORY_URL>` with the URL of your GitHub repository.

### 2. Create a Virtual Environment

**Windows PowerShell**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**macOS / Linux**

```bash
python -m venv .venv
source .venv/bin/activate
```

### 3. Install Dependencies

```bash
pip install -r requirements.txt
```

The requirements file includes dependencies for both the local application and the Kaggle inference environment. Some packages may already be installed in Kaggle.

### 4. Configure the Kaggle Notebook

Open `kaggle_api.ipynb` in Kaggle and run its cells in the required order.

1. Enable a GPU under the notebook's accelerator settings.
2. Open Kaggle Secrets.
3. Add `NGROK_AUTHTOKEN` with your ngrok authentication token.
4. Optionally configure `API_SECRET` to use your own API authentication secret.
5. Run the notebook cells and wait for the model and API to become ready.

The notebook loads Qwen3-14B and starts the authenticated FastAPI endpoint through ngrok. Depending on available GPU memory, it may use the 4-bit `Qwen/Qwen3-14B-AWQ` model.

The quantized configuration may require the additional `autoawq` package.

Copy the API URL and secret printed by the notebook. Keep the Kaggle session running while using the local application.

### 5. Configure Environment Variables

Create a local `.env` file in the project root using `.env.example` as a template.

```env
KAGGLE_API_URL=
API_SECRET=
```

Set the values as follows:

- `KAGGLE_API_URL`: The base ngrok URL printed by the Kaggle notebook.
- `API_SECRET`: The secret configured or generated by the Kaggle API.

**Important:** Enter the base URL without appending `/generate`, because `app.py` adds that endpoint path automatically.

Never place real credentials in `.env.example`, source code, or a public notebook.

### 6. Run the Application

Once the Kaggle API is running and `.env` is configured:

```bash
streamlit run app.py
```

Open the local URL displayed in the terminal.

## 🔍 RAG Pipeline Details

The RAG implementation in `rag.py` follows these steps:

1. Split the document into chunks.
2. Generate embeddings with `intfloat/multilingual-e5-base`.
3. Build a FAISS vector index.
4. Embed the user's question.
5. Retrieve the four most relevant chunks.
6. Build a prompt using the retrieved context and question.
7. Send the prompt to Qwen3 through the Kaggle API.
8. Display the generated answer and retrieved source chunks.

The embedding implementation adds the E5-specific `passage:` and `query:` prefixes and normalizes embeddings.

The RAG prompt instructs Qwen3 to answer using only the supplied context. If retrieval returns no chunks, the application returns a fallback response without calling the model.

The current implementation does not include conversational memory. Follow-up questions do not automatically retain previous questions and answers as conversation history.

---

## 📝 Summarization Pipeline Details

The summarization logic is implemented in `app.py`.

For shorter documents, the application sends the text to the model in one request.

For longer documents, it uses map-reduce:

- **Map:** Each chunk is summarized independently.
- **Reduce:** Partial summaries are combined into a final summary.

The summarization chunk size is configured separately from the chunk size used for RAG.

---

## 🧩 Structured Extraction Pipeline Details

The extraction logic is implemented in `extraction.py`.

1. Define the output schema in `DocumentInformation`.
2. Build a prompt from the schema and document text.
3. Call the Qwen3 API.
4. Parse the model response into a JSON object.
5. Validate the object with Pydantic.
6. Retry with a correction prompt when parsing or validation fails.

The schema controls the requested output fields. Missing information can be represented by `null` for string fields or empty lists for list fields.

## 🛠️ Error Handling & Troubleshooting

The application handles common errors, including:

- Invalid, empty, or unreadable PDFs
- Documents with no extractable text
- Embedding and FAISS indexing failures
- Invalid model responses
- Kaggle API authentication failures
- Unavailable Kaggle sessions or ngrok tunnels
- Invalid extraction JSON or validation failures

### HTTP 401 — Unauthorized

Check that `API_SECRET` in `.env` matches the secret configured by the Kaggle notebook.

### HTTP 503 — Model Not Ready

The model may still be loading. Wait for the notebook to indicate that inference is ready.

### API Unreachable

Check that the Kaggle session is running and that `KAGGLE_API_URL` contains the current ngrok URL.

If ngrok restarts, update the URL in `.env`.

### Null Extraction Fields

A field such as `title` may be `null` if the model cannot find the requested information in the extracted text. Inspect the extracted document text and prompt before changing the schema.

### Scanned PDFs

Image-only or scanned documents may not yield usable text without OCR support. Verify the text extracted by Docling if parsing fails.
